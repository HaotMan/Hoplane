# AI 远程终端管理器 MVP 需求文档

> 版本：V0.1  
> 更新时间：2026-07-20

## 1. 产品目标

开发一个面向 AI Agent 的 SSH 主机管理工具。

用户可以像使用 Xshell 一样保存多台服务器连接，并通过 MCP 或 CLI 将这些服务器提供给 Codex、Claude Code、Cursor 等 AI 使用。

MVP 重点解决：

- 统一管理多台 SSH 主机；
- AI 可以指定服务器执行命令；
- 每台服务器可以配置不同权限；
- SSH 凭据不直接暴露给 AI；
- 所有 AI 操作都有日志。

## 2. MVP 范围

MVP 包含：

1. SSH 主机管理；
2. 凭据管理；
3. 连接测试；
4. MCP Server；
5. CLI；
6. 远程命令执行；
7. 文件上传和下载；
8. 每主机命令与路径限制；
9. 操作日志；
10. 基于 `classfang/ssh-mcp-server` 改造。

MVP 不包含：

- 完整交互式终端；
- Vim、Top、GDB 等 Full Terminal Use；
- 多个 PTY 会话；
- 用户与 AI 终端控制权切换；
- 团队协作和云端同步；
- 复杂审批流。

## 3. 目标用户

- 需要 AI 操作远程开发服务器的开发者；
- 需要 AI 执行巡检、部署和故障排查的运维人员；
- 需要管理多台 AI 可访问服务器的小型研发团队。

## 4. 核心使用场景

### 4.1 多服务器巡检

AI 分别在多台服务器执行：

```bash
df -h
free -h
systemctl status app
```

### 4.2 远程部署

AI 在测试服务器执行拉取代码、构建和部署命令。

### 4.3 数据迁移

AI 可以分别在源服务器和目标服务器执行命令，并上传或下载迁移文件。

### 4.4 日志排查

AI 在指定服务器读取应用日志和系统状态。

## 5. 功能需求

## 5.1 主机管理

用户可以：

- 新增主机；
- 编辑主机；
- 删除主机；
- 测试连接；
- 设置名称、地址、端口和用户名；
- 设置分组和标签；
- 设置默认工作目录；
- 为每台主机绑定凭据和权限策略；
- 从 `~/.ssh/config` 导入主机。

主机状态包括：

- 未连接；
- 连接中；
- 在线；
- 连接失败；
- 认证失败。

## 5.2 凭据管理

支持：

- 密码；
- 私钥；
- 私钥口令；
- SSH Agent；
- SSH Config。

要求：

- 认证信息在创建或编辑主机时直接填写，每台主机独立保存；
- 密码和口令保存在本地加密保险库；
- 数据库只保存凭据引用；
- MCP 和 CLI 不返回密码、私钥内容和口令；
- 不在命令行参数中传递明文密码。
- 用户在主机详情页再次验证保险库主密码后，可限时查看和复制密码、口令及私钥内容；
- 删除主机时自动清理其认证信息。

## 5.3 权限管理

每台主机可以单独配置：

- 命令白名单；
- 命令黑名单；
- 允许上传的远程目录；
- 允许下载的远程目录；
- 允许访问的本地目录；
- 是否允许上传；
- 是否允许下载。

示例：

```text
开发服务器：允许大部分开发命令
测试服务器：允许部署，不允许关机
生产服务器：只允许查看日志和状态
```

未通过权限校验的操作直接拒绝。

## 5.4 MCP 接入

应用提供本地 MCP Server。

MVP 工具：

```text
list_hosts
test_host
execute_command
upload_file
download_file
```

### list_hosts

返回 AI 可以访问的主机列表，不返回敏感凭据。

### execute_command

参数：

```json
{
  "host_id": "host-prod-01",
  "command": "df -h",
  "directory": "/opt/app",
  "timeout_ms": 30000
}
```

返回：

```json
{
  "stdout": "...",
  "stderr": "",
  "exit_code": 0,
  "duration_ms": 320
}
```

### upload_file

将允许目录内的本地文件上传到指定远程目录。

### download_file

将允许目录内的远程文件下载到指定本地目录。

## 5.5 CLI 接入

提供本地 CLI：

```bash
aiterm host list
aiterm host test host-dev
aiterm exec host-dev -- df -h
aiterm upload host-dev ./app.tar /opt/app/
aiterm download host-dev /var/log/app.log ./
```

CLI 必须与 MCP 共用同一套权限和审计逻辑。

## 5.6 操作日志

记录：

- 调用来源；
- AI 客户端；
- 主机；
- 操作类型；
- 命令或文件路径；
- 权限判断；
- 执行结果；
- 开始时间；
- 执行时长；
- 错误信息。

日志不得包含：

- 明文密码；
- 私钥内容；
- 私钥口令；
- Token。

支持按主机、时间和结果查询。

## 5.7 应用界面

MVP 页面：

1. 主机列表；
2. 主机编辑与内联认证页；
3. 主机详情、认证摘要与只读终端页；
4. 权限配置页；
5. Agent 接入页；
6. 操作日志页。

主机列表展示：

- 主机名称；
- 地址；
- 分组；
- 在线状态；
- 权限策略；
- 测试连接按钮。

## 6. 关键流程

### 6.1 新增主机

```text
新增主机
→ 填写连接信息
→ 直接填写该主机的认证信息
→ 测试连接
→ 设置权限
→ 保存
```

### 6.2 AI 执行命令

```text
AI 调用 execute_command
→ Core 查询主机
→ 检查权限
→ 建立或复用 SSH 连接
→ 执行命令
→ 记录日志
→ 返回结果
```

### 6.3 AI 切换服务器

AI 不需要切换 GUI，只需在每次调用中指定不同的 `host_id`。

```text
execute_command(host-a, ...)
execute_command(host-b, ...)
```

## 7. 非功能要求

### 安全

- MCP 默认只允许本机访问；
- SSH 主机指纹校验默认开启；
- 凭据不得明文落盘；
- 高风险命令应默认禁止；
- 建议使用独立低权限 SSH 账户。

### 性能

- 支持至少 100 个主机配置；
- 支持至少 20 个并发 SSH 连接；
- 本地权限校验耗时应小于 100 毫秒；
- 单台主机失败不得影响其他主机。

### 平台

优先支持：

1. macOS；
2. Windows；
3. Linux。

## 8. MVP 验收标准

1. 可以新增、编辑、删除和测试 SSH 主机；
2. 支持密码和私钥认证；
3. 可以导入 SSH Config；
4. AI 可以通过 MCP 查看主机列表；
5. AI 可以指定不同主机执行命令；
6. AI 可以上传和下载文件；
7. 每台主机可以设置不同命令和路径权限；
8. 未授权操作会被拒绝；
9. AI 无法读取 SSH 凭据；
10. 所有操作均有日志；
11. 修改一台主机不会断开其他主机；
12. MCP 客户端重新连接后可以继续使用。

## 9. MVP 迭代顺序

### 第一阶段

- Fork `ssh-mcp-server`；
- 验证多主机、命令执行和文件传输；
- 完成最小桌面界面。

### 第二阶段

- SQLite 主机管理；
- 本地加密保险库；
- 动态增加和修改主机；
- 每主机权限策略。

### 第三阶段

- MCP 和 CLI 统一接入；
- 操作日志；
- 打包发布。
